# Issue tracker: GitHub

Issues and specs live in brandonramsey/bramsey-eslint on GitHub.
Use the gh CLI from this repository.

Read issues with their comments and labels; check existing issues before
creating new ones. Prepare multiline bodies in files and use --body-file.

Present the ticket summary for user review before submitting issues.
After approval, create tickets in dependency order and apply the configured
triage labels. Use native blocking relationships where available; otherwise
include explicit blocking issue references. Link children to an existing
parent when applicable.

PRs as a request surface: no.
