# Domain docs

This repository uses one domain context: root GLOSSARY.md and docs/adr/.

Before exploring, read GLOSSARY.md and the ADRs relevant to the work.
Proceed when a referenced document is absent; create domain documents
when terms or decisions are resolved.

Use the glossary's canonical terms in designs, tickets, and reviews.
Surface conflicts with existing ADRs before changing direction.
Record resolved terminology in the glossary. Record architectural
tradeoffs in ADRs when their cost and context justify a decision record.
