# Publish configuration and plugins without a runner

On October 8, 2026, the maintainer limited the planned Oxlint package to configuration and bundled plugins, with Oxlint as a peer dependency. Consumers own invocation, file selection, fixing and exit handling; the package publishes compiled ESM configuration/plugin modules and declarations, but no lint executable, preflight command or repeated-fix orchestration. Bundle oxlint-tsgolint and the required plugin/provider dependencies; keep the consumer's TypeScript dependency contract separate from tsgolint's embedded compiler.

The maintainer accepted unenforced disable-comment explanations as a configuration-only limitation. The validated direct bridge crashes, and clamping permits self-suppression; the independent preflight remedy requires execution outside the selected package boundary. This supersedes ADR 0014's runner/preflight requirement, while retaining configured unused-directive errors and blanket-disable rejection. It also revises ADR 0005's engine/dependency arrangement for the migration. The current ESLint package remains unchanged until implementation.

ADR 0015's inferred-coverage warning remains a bundled plugin-rule obligation, with configured syntax-only/declaration exemptions. Repeated fix convergence is consumer-owned: document the measured multi-pass behavior without promising one invocation reaches the former ESLint output.

The maintainer further narrowed permanent tests to this package's public surface: exports and declarations, configured rules/options, public factory composition and validation, plugin exports/specifiers, dependency metadata, packaged assets, and generated-example equivalence/drift. Assume Oxlint and upstream plugins work. Remove the consumer execution harness and Oxlint smoke invocation; do not add per-rule diagnostics/fix fixtures, compiler-program compatibility suites, or internal resolver/graph/lifecycle regression suites. Inspect the packed artifact and public modules directly without installing a temporary consumer or launching the lint engine. Repository self-linting remains a development command, not an engine behavior test. This supersedes broader test obligations in the earlier proposal and historical issue handoffs.
